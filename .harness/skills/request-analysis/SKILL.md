# Request Analysis

## 读取

1. `.harness/README.md`
2. `.harness/rules/开发流程规范.md`
3. `.harness/rules/工程结构.md`
4. 与需求直接相关的 Wiki、代码、测试和现有变更档案

## 步骤

1. 提炼目标、用户价值、验收标准、非目标和授权边界。
2. 用代码搜索定位真实入口、调用链、状态、配置、测试和文档。
3. 识别相邻功能、重复实现、兼容性和失败恢复。
4. 按需分析接口、Agent/Prompt、数据、权限、环境、部署和回滚影响。
5. 从 `.harness/changes/_template/summary.md` 创建或更新变更档案。
6. 对会显著改变方案的歧义请求用户确认；其余用明确假设继续推进。

## 输出要求

- 只写已取证事实与明确标注的推断。
- 文件清单包含动作、原因和配套测试。
- 记录风险、不变量、开放问题和用户授权边界。
- 未经确认不把状态推进到 `approved`。
