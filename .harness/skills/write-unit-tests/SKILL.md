# Write Unit Tests

## 步骤

1. 阅读测试、编码规范和相关变更档案。
2. 定位最接近的现有测试、fixture 与外部边界。
3. 对缺陷先写能稳定失败的最小用例。
4. 覆盖正常、边界、非法输入、状态一致性、权限和依赖降级。
5. 在 adapter/client 边界 mock 网络、数据库、模型和计费服务。
6. 运行最小测试，再运行与风险匹配的回归门禁。
7. 记录真实结果和未验证边界。

## 质量标准

- 验证可观察行为与不变量，不绑定无意义实现细节。
- fixture 使用虚构、最小、不敏感的数据。
- 时间、随机、环境和并发可控制。
- 断言具体，失败信息能定位契约。
- AI 生成测试必须加入人工推导的边界或反例。

本技能默认不修改产品实现；若最小失败用例暴露缺陷，记录后转交 `implement-change`。
