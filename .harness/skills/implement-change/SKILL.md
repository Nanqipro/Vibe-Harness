# Implement Change

## 前置

读取 `.harness/README.md`、匹配的变更档案以及其直接要求的工程、编码、测试和领域资料。没有获批方案且变更复杂时，先使用 `request-analysis`。

## 步骤

1. 检查工作树并保护用户已有改动。
2. 验证变更档案中的代码入口和假设。
3. 将状态推进到 `in_progress`，按最小闭环实施。
4. 同步修改实现、测试、配置、文档和可观测性。
5. 对外部输入、权限、副作用、并发和失败恢复添加确定性护栏。
6. 先运行专项验证，再运行与风险匹配的质量门禁。
7. 将真实结果和未验证边界写回档案，进入 `verifying`。

## 边界

- 不擅自扩大需求或重构无关代码。
- 不覆盖、回滚、暂存、提交或推送用户改动，除非获得授权。
- 不调用未经授权的生产、共享、付费或写入型服务。
- 不用放宽测试、吞错或伪造结果解决失败。

## 完成

验收标准、必要测试、文档、风险和回滚均有证据后，才能标记 `done`。
