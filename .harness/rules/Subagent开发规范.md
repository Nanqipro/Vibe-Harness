# Subagent 开发规范

## 适用范围

本规范用于 subagent 的新增、拆分、合并、改名、工具扩展、Prompt 调整、状态变更、路由开放和用户界面事件接入。接入项目后，应把实际注册点、状态模型、事件链和测试路径补到项目 Wiki，而不是写死在通用规范中。

代码、框架版本和可重复测试结果高于历史文档或注释。

## 核心边界

1. **用稳定的功能名标识 Agent。** 内部名称、配置 key、路由 label 和注册名保持一致；展示名称可以本地化，但不应形成多套身份映射。
2. **一个 subagent 负责一个清晰领域闭环。** 描述必须写明适用与不适用场景、必填输入以及读写边界。
3. **主 Agent 负责协调，subagent 持有叶子工具。** 不要把所有领域工具平铺给主 Agent，也不要创建继承全部权限的通用逃生 Agent。
4. **默认只读、最小权限。** 写入、删除、发布和生产重试必须有明确授权、幂等、审计和失败恢复。
5. **输入契约自包含。** subagent 不应假定可以看到全部对话；委派描述须包含原问题、已提取字段和必要上下文。
6. **用户输出不泄露内部编排。** 除非产品明确要求，不主动展示内部 Agent 名、工具名、状态字段或推理过程。

## 推荐结构

| 内容 | 推荐落点 | 约束 |
|---|---|---|
| Agent spec 与轻量编排 | 项目的 agent/subagent 模块 | 只做契约、工具选择和适配 |
| 长 Prompt | 集中的 Prompt 目录 | 可版本管理，不维护字符串副本 |
| 领域工具 | 对应领域模块 | 返回完成判断所需的最小结构 |
| 外部 client | 通用集成层 | 只做鉴权、请求、响应校验与异常归一 |
| 共享状态 | 编排层状态模型 | 只保留跨步骤所需的最小状态 |
| 测试 | 项目测试目录 | mock 外部边界，不调用生产或计费服务 |

工具 schema、docstring 和 Prompt 都属于行为契约，必须随实现一起审查与测试。

## Spec 契约

```python
EXAMPLE_SUBAGENT = {
    "name": "example_agent",
    "description": "适用边界、不适用边界和必填输入",
    "system_prompt": "工作流、工具纪律、错误处理和输出契约",
    "tools": ["example_tool"],
}
```

- `name` 是全链路唯一标识；改名属于契约变更。
- `description` 必须能区分相邻 Agent，避免泛化能力宣传。
- `system_prompt` 说明输入解释、工具顺序、停止条件、缺字段、拒答、降级和输出。
- `tools` 只列完成职责必需的工具，并能从注册表解析为真实对象。
- 工具参数细节以 schema/docstring 为事实源，避免在 Prompt 中复制后漂移。
- 模型或中间件默认继承主编排配置；覆盖时说明原因并补构建测试。

## 注册闭环

新增、改名、启停或改变职责时，逐项检查：

- 实现模块与公开导出；
- Agent 和工具注册表；
- 主路由的能力描述与相邻边界；
- 环境开关与默认启用策略；
- 命令、界面和展示映射；
- 路由 taxonomy 与评估样本；
- 架构文档和测试。

关闭某个 subagent 后，其 spec、叶子工具和主 Prompt 中的能力说明都不得继续暴露。

## 工具与确定性护栏

- 模型只填写业务参数；会话状态和调用标识由框架注入。
- 工具结果必须裁剪、限长并结构化，日志只记录必要标识、计数和错误类型。
- 参数白名单、类型、范围、确认门槛、超时、有限重试和停止条件由代码执行。
- 重试保持用户已确认参数，不允许模型为了成功擅自修改关键输入。
- 数据不足或外部系统降级时明确输出未知，不伪装成功或无证据归因。
- 写操作提供幂等键、权限校验、审计记录和恢复路径。

## 状态生命周期

- 只保存跨步骤需要的查询标识、确认参数、作用域、缓存签名和可恢复进度。
- 大结果保存在有界缓存或外部存储，不塞入会话状态。
- 缓存 key 覆盖所有影响结果的上下文，并有容量、时效和失效策略。
- 主上下文变化时清空不再适用的结果和缓存。
- 共享字段在主状态与 subagent 状态之间保持名称、类型和语义一致，并由测试守护。
- 明确区分每轮重置字段与跨轮粘滞字段。

## 外部调用

- 秘密从项目批准的配置或环境机制解析，不进入状态、工具消息或用户输出。
- client 使用合适的异步/同步 I/O、显式超时、响应校验和稳定错误类型。
- 分页、轮询、重试、缓存和 payload 大小都设置硬边界。
- 未经用户明确授权，不调用真实模型网关、生产接口、共享数据库写操作或计费服务。

## Prompt、流式输出与持久化

- Prompt 变更必须有直接测试或适当规模的评估回归。
- 只向用户展示最终允许公开的输出；内部模型流和推理过程不直接透传。
- 事件协议应至少区分开始、增量、完成、错误和取消。
- 保存前清除不可序列化对象、凭据和无界原始响应。
- 长任务持久化状态、进度、计数和错误，不能只依赖内存或对话窗口。

## 完成定义

- [ ] 职责、输入和读写边界明确
- [ ] 注册、开关、路由和展示映射一致
- [ ] 工具权限最小且 schema 可解析
- [ ] 状态、缓存和上下文失效有测试
- [ ] Prompt 的成功、缺字段、失败与降级路径有覆盖
- [ ] 外部调用已 mock，副作用需要明确授权
- [ ] 流式输出、持久化和最终文本无重复或泄露
- [ ] 相关文档、评估集和变更档案已同步
- [ ] 专项测试与项目质量门禁通过
