# 测试规范

## 基本要求

所有功能和缺陷修复都应提供与风险匹配的自动化测试。测试应验证外部行为、不变量和失败边界，而不是仅复述实现。

## 覆盖重点

- 正常路径、边界值、空值、非法值和重复请求；
- 权限、幂等、事务、并发、超时、重试和降级；
- 状态、缓存、注册表、配置和展示映射的一致性；
- 外部依赖失败、部分响应和不可信数据；
- 缺陷修复对应的最小失败用例。

## 隔离

- 单元测试默认不访问网络、生产服务、共享数据库或计费模型。
- 在 client/adapter 边界 mock 外部依赖。
- fixture 使用虚构、最小和不敏感的数据。
- 时间、随机数、环境变量和并发行为应可控制。

## 分层

| 层 | 目标 |
|---|---|
| 单元/专项 | 快速验证局部行为和回归 |
| 集成 | 验证模块、存储或协议边界 |
| 接口/端到端 | 验证真实入口与关键用户路径 |
| 静态检查 | 验证格式、类型、依赖和安全规则 |
| 评估 | 验证 Agent/Prompt 的语义行为与指标 |

具体命令以 `.harness/wiki/环境与运行.md` 为准。不得把跳过、预期失败或未运行描述为通过。
