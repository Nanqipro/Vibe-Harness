# AI 功能开发规范

## 确定性优先

- 映射、校验、状态机、计数和集合推导优先使用确定性代码。
- 模型负责需要语义判断的部分，不承担可机械验证的工作。
- Agent、工具、标签、展示名称和环境开关尽量从单一注册表派生。

## Agent 与路由

- 修改 subagent 时同时遵循 `.harness/rules/Subagent开发规范.md`。
- 检查构建、注册、路由、工具权限、状态、界面、持久化和评估闭环。
- 职责与权限保持聚焦，不创建继承全部能力的万能 Agent。
- 关闭能力后，Prompt、工具和路由中不得继续暴露。

## Prompt

- Prompt 是行为代码，必须进入版本控制、审查和验证范围。
- 明确输入契约、输出结构、工具纪律、缺字段、拒答、异常与降级路径。
- 长 Prompt 集中维护；可调用技能与普通 Prompt 分开组织。
- 变更路由、判官或工具选择时运行直接测试和适当规模的评估。

## 测试与评估

- 单元测试默认禁止真实调用模型网关、生产接口或计费服务。
- mock 合法输出、结构包裹、空值、缺字段、非法格式、超时和预算错误。
- 加入独立边界与反例，避免 AI 生成测试只验证 AI 生成实现的同一假设。
- 真实评估前确认授权、预算、样本规模、指标和停止条件。
- 认证、网络、预算与模型行为错误必须分类，不混为业务缺陷。

## 可观测性与安全

- 长任务持久化进度、错误、计数和最终状态。
- 日志使用最小关联标识，不输出秘密、个人数据或大段原始模型响应。
- 模型输出在产生外部副作用前经过权限、schema 和确定性校验。
- 未完成端到端验证时不得宣布功能完成。
