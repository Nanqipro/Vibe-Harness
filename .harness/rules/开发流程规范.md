# 开发流程规范

## 开始前

1. 阅读 `.harness/README.md` 并选择一个主技能。
2. 定位匹配的变更档案；没有且属于跨文件或高风险变更时，从模板创建。
3. 确认目标、验收标准、非目标和用户授权边界。
4. 检查工作树，保留用户已有改动。

## 实施

- 先验证当前事实，再修改代码。
- 让实现、测试、文档和变更档案同步推进。
- 优先小范围、可回滚的改动。
- 发现方案与事实冲突时更新变更档案，不静默扩大范围。
- 外部写入、生产环境、付费服务和破坏性操作必须获得明确授权。

## 验证

1. 运行最小专项检查。
2. 运行与风险匹配的快速、静态、接口或全量门禁。
3. 记录真实命令、退出状态和未验证边界。
4. 失败时先分类根因，不通过放宽断言或隐藏错误制造绿色结果。
5. 高风险变更进入独立专家审查和发布验证。

## 完成

只有在验收标准满足、必要测试通过、文档同步、风险可接受且无隐藏副作用时，才能标记完成。未执行的检查必须明确写为未验证。
